## GitとGitHubは何から始めるべきか

Gitの基本操作は「init」「add」「commit」「push」の順で覚えます。最初はコマンドラインに抵抗があるなら、GitHub DesktopなどのGUIツールを使う手もあります。RUNTEQやフィヨルドブートキャンプの課題提出はGitHub経由が多く、GUIツールで操作を理解しやすい環境です。

初日にリポジトリの作成（init）から始め、2日目に変更をステージング（add）、3日目に変更を確定（commit）、4日目にリモートへ反映（push）を実践しましょう。練習用リポジトリを用意すると失敗しても問題ありません。スクールの課題はポートフォリオ制作にもつながり、コミット履歴も評価対象になっています。

## ブランチとプルリクエストはいつ習得するか

基本操作に慣れたら、5日目から「branch」と「pull request（プルリク）」の使い方を学びます。RUNTEQは転職特化で実践的なチーム開発経験を提供しており、ブランチ運用やプルリクの流れを実務に近い形で身につけられます。フィヨルドブートキャンプもチーム開発の指導があり、実際にプルリクを経験できます。

ブランチは新機能の追加やバグ修正で使うもの。まずは自分のリポジトリでブランチを切り、変更をプルリクでメインブランチに統合する流れを実践してください。個人開発ならGitHubのWeb画面でプルリクを作成し、マージまで試すのが手軽です。

## GitとGitHub学習でつまずきやすいポイントは何か

Gitの操作は初めてだとコマンドの意味が分かりづらい。たとえば「add」と「commit」の違いが理解できず、作業が止まるケースがある。GUIツールを利用すると視覚的に状態が分かりやすくなるため、最初は公式のGitHub Desktopなどを使うのも手だ。

GitHubのプルリクエスト（Pull Request）も慣れが必要だ。コードの変更をレビュー依頼する流れは、最初は複雑に感じるが、スクールの課題提出で自然に身につく。RUNTEQは転職特化でGitHubを使った課題提出が必須なため、9ヶ月の学習期間で確実に慣れる設計だ。

一方、フィヨルドブートキャンプは月額制で短期間でも始めやすいが、転職支援が明記されていないため、GitHubの活用が仕事に直結する経験は自己管理が求められる。操作で詰まった場合は公式ドキュメントを参照しつつ、基本のコマンドを手順通り繰り返すことが効果的だ。

## GitとGitHub学習の初週に今日やるべき3つの具体的手順

1. GitHubにアカウント登録し、GitをPCにインストールする。公式サイトから無料で入手可能。

2. ターミナルまたはGitHub Desktopを使い、ローカルリポジトリを作成（git init）、ファイルを追加（git add）、コミット（git commit）までを繰り返す。

3. GitHubにリモートリポジトリを作り、ローカルの変更をプッシュ（git push）し、Pull Requestの作成まで一連の流れを体験する。

この3ステップでGitとGitHubの基本的な操作が手を動かしながら理解できる。時間配分は1日目にインストールと初期化、2日目にコミットとプッシュ、3日目以降にプルリクエスト作成とブランチ操作に挑戦すると効率的だ。

実践的な学習を志すなら、RUNTEQのような転職支援付きスクールか、フィヨルドブートキャンプの月額制で継続学習を検討してみると良い。

操作の習得にはコマンドライン（ターミナル）とGUIツールの両方を用意すると理解が深まります。RUNTEQやフィヨルドブートキャンプでは、課題提出がGitHub経由のため、GitHub Desktopなどの公式GUIツールを推奨しています。GUIは視覚的に状態把握がしやすく、初心者のつまずきを減らせます。

また、テキストエディタはVSCodeなどの無料エディタを準備してください。GitやGitHubと連携できる拡張機能があり、コミットの差分確認やブランチ切り替えなどの操作を補助します。実際にRUNTEQのカリキュラムでもVSCodeが推奨され、作業効率アップに役立っています。

回線環境も重要です。GitHubへのプッシュやプルリク作成はオンラインが前提で、安定したネット回線が必要です。特にフィヨルドブートキャンプは月額制で継続学習が前提のため、ネット環境が整っているか確認してください。

このようにGitインストール、GitHubアカウント作成、GUIツール導入、テキストエディタ準備、安定ネット環境の5点を初日に用意すると学習がスムーズに進みます。RUNTEQやフィヨルドブートキャンプの公式資料にもこれらの準備が推奨されています。

### GitHubのプルリクエストの仕組みが分からない場合、どのように理解を深めれば良いですか？

プルリクエスト（PR）はGitHubの中でも特に初心者が戸惑いやすい機能です。これは「変更内容をチームメンバーにレビューしてもらい、問題なければメインブランチに統合する」仕組みです。単にファイルを上書きする「push」とは異なり、変更の提案から承認までの流れが含まれます。

理解を深めるには、まず個人リポジトリで模擬的にPRを作成することを推奨します。RUNTEQやフィヨルドブートキャンプではチーム開発課題で実際にPRを経験できる設計です。個人学習の場合は、GitHubのWeb画面で新たにブランチを切り、変更をコミット後、「Compare & pull request」ボタンを押してPRを作成し、マージまで行います。

この過程で「レビューコメントを付ける」「自分でコメントを返信する」などの操作も体験すると理解が深まります。PRは単なる操作だけでなく、コミュニケーションツールとしての側面も持つため、編集部は「実務準備に欠かせない協働スキルを育てる場」と読みます。

また、GitHubの公式ドキュメントや動画チュートリアルも役立ちます。特にスクールのカリキュラムでPR作成が課題になっている場合、課題の指示書に沿って手順を追うのが実践的です。RUNTEQは転職支援付きのため、PR運用の実務感覚を身につける機会が豊富です。

PRの仕組みがわからず手が止まる場合は、一度GUIツールのPR機能を試すと視覚的に理解しやすいです。例えばGitHub DesktopからPR作成画面に誘導されるので、初心者でも操作ミスを減らせます。こうしたツール活用も初週の学習に取り入れてください。
